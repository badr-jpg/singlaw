# Decisions

Running log of calls made without asking, per working style.

1. **Python 3.12 via uv.** System python is 3.9 (< 3.11 floor). `uv` manages the venv and lockfile; Makefile wraps it.
2. **Model profiles.** `MODEL_PROFILE=full` (default): `Qwen/Qwen3-Embedding-0.6B` + `jinaai/jina-reranker-v2-base-multilingual` per spec. `dev`: MiniLM embedder + ms-marco cross-encoder (~120 MB total) for fast local iteration. `stub`: deterministic hash embeddings + lexical-overlap reranker, zero downloads — unit tests run offline. Reranker swappable to `Qwen/Qwen3-Reranker-0.6B` via `RERANKER_MODEL`.
3. **Sparse vectors.** bm25s tokenizer (stopwords+stemming) → stable 32-bit token hashes → doc-side BM25 TF component; Qdrant sparse vectors with `Modifier.IDF` so IDF stays corpus-consistent as ingest grows (no re-encoding old docs). avgdl kept as rolling stat per collection.
4. **Citation marker protocol.** LLM emits `[CITE:n]`; a `sources` SSE event maps `n` → legal citation + SSO URL; frontend renders chips. Grounding validator rejects/flags sentences with no marker and markers with no source. Rendered form is the legal citation, never `[3]`, satisfying the spec.
5. **LLM call budget per query:** 1 analysis call + 1 combined rewrite+HyDE call + 1 generation call. Analysis and rewrite degrade to heuristics (regex citation extraction, no rewrites) when no API key is set, so retrieval works fully offline.
6. **SSO parser is pattern-based**, driven by provision-number regexes over structure with tolerant selectors, tested against fixtures modelled on SSO markup. Exact live selectors must be verified during the first real 05:00–07:00 crawl window; parser logs unparsed residue instead of guessing.
7. **Seed corpus.** `data/archive/` ships abbreviated but realistic SSO-format fixtures (Employment Act, PDPA excerpts, etc.) + sample judgments so the system runs end-to-end offline. Not the real corpus; `--seed-from-archive` loads any pre-fetched archive with the same manifest layout.
8. **Single local user.** `user_docs` namespaced under user id `local`; schema carries `user_id` so multi-user later is a config change, per non-goals.
9. **Treatment pass is conservative:** `overruled` only when a later, same-or-higher court uses explicit overruling language within a window around the citation; anything ambiguous stays `unknown`/`distinguished`. False negatives preferred over false "overruled".
10. **Extra endpoints beyond spec** (PATCH conversation rename, `/api/corpus/*`, `/api/chunks/{id}`, `/api/law/{citation}/citing`) — required by the specced frontend features (rename, source explorer, side panel, citing-judgments view).
11. **Skipped the brainstorming skill; plan executed inline.** The build prompt is a complete spec and the session is autonomous; wrote `docs/superpowers/plans/2026-08-11-sg-law-rag.md` and executed in-session. Frontend built by a parallel subagent against the frozen API contract.
12. **git init done, no commits** — harness policy is to commit only when asked. Tree left clean for review.
13. **Answer validation is post-hoc on the stream.** Tokens stream immediately (spec requires SSE); the validator runs on the full text and emits a `validation` event; UI flags unsupported material. A blocking pre-validation pass would kill streaming latency.
14. **SQLite one file** (`data/db/app.sqlite3`), WAL; all writes serialized through a single writer using an `asyncio.Lock` + `flock` on a sidecar lockfile so multiple uvicorn workers stay safe. Citation graph lives in SQLite (`citation_edges`), not Qdrant.
15. **MiniMax default model `MiniMax-M1`**, base URL `https://api.minimax.io/v1`, OpenAI-compatible; `LLM_BASE_URL`/`LLM_MODEL` env swap it for local vLLM with zero call-site changes.
16. **Rank-percentile CE component in the authority blend.** Min-max amplified small score gaps (an overruled case with top CE outranked the CA decision); pure sigmoid saturates on logit rerankers (ms-marco emits −9…−11 on cross-domain pairs, flattening everything to ties). Rank percentile is scale-robust across rerankers; the coverage check still uses the absolute sigmoid score. Found via live testing on real models, covered by tests.
17. **Startup dimension guard.** `ensure_collections` now fails loudly when the stored vector dim ≠ the configured embedder's dim ("reindex with make clean && make seed") — a stub-profile run against the real data dir had silently created 256-dim collections that only exploded at query time.
18. **Embedded Qdrant is single-process.** `make eval` while `make dev` runs blocks on the storage lock — documented in the Makefile and eval script. The crawler CLI ends with `os._exit(0)`: torch/tokenizer non-daemon threads otherwise kept the process alive after all work was committed.
19. **LLM default is `MiniMax-M2.7`** (2026-08-12): verified against the live `/v1/models` listing (which also offers `MiniMax-M3`, `-highspeed` variants). M-series are reasoning models that emit `<think>…</think>` inline over the OpenAI-compatible API, so the provider strips it — a stateful streaming filter (tags can split across deltas) plus `strip_think` on non-streaming calls — and per-call `max_tokens` budgets were raised (analysis/rewrite 3000, generation 8000, user-doc context 1500) so thinking can't starve the visible reply. Without the filter, chain-of-thought would stream into answers and the grounding validator would flag it.
20. **Reranker fallback to Qwen3-Reranker-0.6B** (2026-08-12): `jinaai/jina-reranker-v2-base-multilingual`'s `trust_remote_code` modeling code imports an API removed from modern `transformers`, and pinning `transformers` down would break the Qwen3 embedder. The registry now tries jina and, on ImportError, falls back loudly (warning log) to `Qwen/Qwen3-Reranker-0.6B` — the spec's sanctioned alternative — run causal-LM yes/no scoring on MPS when available. `RERANKER_MODEL` still overrides. Also: model loads are cache-first (`HF_HUB_OFFLINE` during first attempt) because unauthenticated Hub revalidation is rate-limited and stalled warm-cache startups for minutes.
21. **Phase-2 sources** (MAS/PDPC/IRAS/Hansard) are representable today: `doc_type` is an open string enum in storage, `authority_tier` 6 covers guidance, and the parser registry keys on source domain. No ingest wired, per spec.
22. **Billing is plan metadata first, Stripe optional** (2026-10-07). Plans (`personal` free · `business` S$29/mo or S$290/yr · `teams` "talk to us") live as a `PLANS` list in `backend/app/billing.py`, not in the DB: the prices are placeholders pending the owner's pricing decision and change with a one-line edit; `GET /api/billing/plans` serves them verbatim. The active plan is one kv row (`plan`, default `personal`) so the single-user deployment needs no accounts table, and `GET /api/billing/status` computes usage live from SQLite. Checkout works only when `STRIPE_SECRET_KEY` + `STRIPE_PRICE_IDS` are set (a subscription Checkout Session is created server-side with the `stripe` SDK and redirects to `PUBLIC_BASE_URL/billing?checkout=…`); otherwise `POST /api/billing/checkout` answers 503 and the UI falls back to `POST /api/billing/waitlist` (`billing_waitlist` table; regex email check rather than an `email-validator` dependency). `POST /api/billing/webhook` verifies Stripe signatures when `STRIPE_WEBHOOK_SECRET` is set; without it, events are accepted unverified only if a Stripe key is configured at all (dev convenience for `stripe listen`), and refused with 503 when nothing is configured, so an unconfigured deployment cannot have its plan flipped by an anonymous POST. Per-plan limits are informational for now: the only enforced cap is `MAX_BUSINESSES` (default 3 → 403 on `POST /api/businesses`), as the contract specifies; per-plan document limits are not enforced.
23. **Regenerate and empty-conversation semantics** (2026-10-07). `regenerate: true` deletes the conversation's final message only if it is an assistant turn — an earlier answer is never touched, so a user message whose generation failed is simply re-answered — and re-runs the last user message without inserting a new user turn. A conversation created empty via `POST /api/conversations` keeps the default title until its first message arrives, which then titles it exactly like a conversation started from `/api/chat`; otherwise every UI-created thread would stay "New conversation" forever.
24. **SingLaw UI adopted as the product frontend (2026-10-07).** The Lovable-built TanStack Start app (github.com/badr-jpg/singlaw-ai-explorer) replaces the earlier React UI. It was converted from an SSR TanStack Start app to a plain Vite SPA so FastAPI keeps serving a single process (`frontend/dist`), and Lovable's SSR entry, error reporting and CDN-hosted publisher logos were removed (local monogram tiles under `public/sources/`). Routing kept as designed: `/` is the chat workspace, `/welcome` the marketing page. Every placeholder in the prototype — localStorage threads, canned "illustrative" answers, static source list, unanalysed attachments, no-op feedback, "coming soon" plans — is backed by real endpoints (contract v2 addendum in the plan doc). The previous frontend is preserved in git history (commit c075dd4).
25. **Plan limits are governed by the active plan**, not a flat config cap: `POST /api/businesses` and `POST /api/documents` enforce the current plan's `limits` (Personal 1 workspace / 10 documents, Business 3 / 100, Teams unlimited). `MAX_BUSINESSES` survives only as an optional operator ceiling (0 = follow the plan). This keeps `/api/billing/status` and the enforcement consistent so the UI's "n of m used" is never contradicted.
26. **Answer latency work (2026-10-08).** Measured per stage: the local pipeline is ~1.1 s (embedding + Qdrant 0.2 s, Qwen reranker 0.9 s); the cost is sequential MiniMax reasoning round-trips (baseline: analysis 11.7 s → rewrite+HyDE 18.6 s → ~8 s to first answer token; 58 s total). No API parameter disables thinking (`reasoning_effort`, `thinking`, `enable_thinking`, `reasoning_split` all probed — ignored), and every model variant spent 25–40 s on the combined rewrite+HyDE prompt, so the fixes are structural: (a) helper calls (analysis, rewrites, HyDE, document context) go to `LLM_FAST_MODEL` (`MiniMax-M2.7-highspeed`, ~2× faster) while the answer stays on `LLM_MODEL`; (b) analysis, rewrites and HyDE run concurrently as three terse calls instead of two sequential ones; (c) one wall-clock pre-stage budget (`LLM_PRESTAGE_BUDGET_SECONDS`, 15 s) — past it analysis falls back to the heuristics and whatever enrichment arrived is used, while late calls still finish to warm (d) a per-question SQLite cache of analysis/rewrites/HyDE, so repeated, trending and Wow-Me questions skip the pre-stage entirely. Every stage's duration ships in the `done` event (`timings_ms`) and the inspector shows "Where the time went". Result: cold ≈ 30 s (capped), warm ≈ 10–14 s (generation only). Remaining floor is the answer model's own thinking; switching `LLM_MODEL` to the `-highspeed` variant would roughly halve generation time — left as the owner's cost/quality call.
