# Singapore Law RAG Assistant — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **Deviation note:** this session is autonomous and the author executes the plan inline immediately after writing it, so tasks are specified at file/interface granularity rather than 2–5-minute steps with duplicated code. The spec (the user's build prompt) is the requirements source of truth.

**Goal:** Offline-capable, locally-hosted RAG assistant for Singapore law: authoritative corpus (`sg_law`) + per-user documents (`user_docs`), hybrid retrieval with legal-domain stages, strictly grounded MiniMax generation, React frontend with trust surfaces.

**Architecture:** FastAPI backend (async), Qdrant embedded (named dense+sparse vectors, two collections), in-process sentence-transformers embedder + cross-encoder reranker, bm25s-tokenized hashed sparse vectors with Qdrant IDF modifier, MiniMax behind a provider interface (generation/rewrite/HyDE only), SQLite (WAL, single-writer) for conversations/documents/crawl-state/citation-graph, React+TS+Vite+Tailwind frontend consuming SSE.

**Tech Stack:** Python 3.12 (uv), FastAPI, qdrant-client (embedded `path=`), sentence-transformers, bm25s, httpx, aiosqlite, BeautifulSoup4+lxml, openai SDK (pointed at MiniMax), React 18, TypeScript, Vite, Tailwind.

## Global Constraints (verbatim from spec)

- Everything except LLM generation runs locally. No network calls for embedding.
- Qdrant embedded mode (`AsyncQdrantClient(path=...)`), no Docker. Payload index creation skipped in embedded mode.
- Two collections, different trust levels: `sg_law` (authority) and `user_docs` (user's factual situation, never authority). Never blended in a flat index.
- SSO automated extraction only 05:00–07:00 Singapore Time, hard kill at 07:00, incremental sync via "What's New", persistent resumable crawl state, polite rate limiting, single connection, backoff on 4xx/5xx.
- Every stored doc: `source_url`, `fetched_at`, `sso_version_date`. AGC attribution on every doc and answer surfacing legislation, baked into answer template.
- Chunk at section level; split oversized at subsection boundaries, never mid-provision. Judgments segmented on `[n]` paragraph numbers.
- Contextual retrieval: structural context derived from parse tree for `sg_law`; LLM context only for `user_docs`, cached aggressively.
- Metadata schema of §2.4 is non-negotiable. Citation graph + treatment pass is a correctness requirement.
- Retrieval: analysis → citation short-circuit → 3 rewrites + HyDE → dense+sparse top-75 each → RRF → top-150 → hard status filters (counted, never silent) → cross-encoder → top-30 → authority-aware blend (configurable, both scores logged) → coverage check → `low_confidence` honoured by answer layer.
- Answers: every proposition cited; citations render as legal citations linking to SSO; temporal basis stated; no parametric gap-filling; SSE streaming; legal-information-not-advice framing; high-stakes referral triggers; s 48 Interpretation Act notice; never draft filings.
- Models load once at startup into a shared singleton. SQLite WAL; single writer with flock-based election.
- Non-goals: no other jurisdictions, no commercial sources, no eGazette backfill, no drafting, no multi-tenancy beyond local namespaces.

## API Contract (frozen — frontend builds against this)

Base URL `/api`. All JSON unless stated. Single local user; no auth.

### POST /api/chat — SSE stream
Request: `{"message": str, "conversation_id": str|null, "doc_ids": [str]|null}`
`text/event-stream`, events in order:

1. `event: meta` — `{"conversation_id": str, "message_id": str, "intent": "statutory_lookup"|"procedural"|"rights_obligations"|"case_law"|"out_of_scope"|"drafting_refused", "low_confidence": bool, "filtered": {"repealed": int, "spent": int, "not_yet_commenced": int}, "temporal_basis": "YYYY-MM-DD", "high_stakes": {"triggered": bool, "reasons": [str], "referrals": [{"name": str, "url": str}]}, "attribution": str, "disclaimer": str, "corpus_last_synced": str|null}`
2. `event: sources` — `{"sources": [{"n": int, "chunk_id": str, "citation": str, "url": str, "doc_type": str, "authority_tier": int, "status": str, "treatment": str, "court": str|null, "decision_date": str|null, "hierarchy_path": [str], "snippet": str, "collection": "sg_law"|"user_docs"}]}`
3. `event: token` — `{"text": str}` (repeated; inline markers `[CITE:n]` reference sources by `n`; frontend renders them as clickable legal citations, e.g. `sources[n].citation`)
4. `event: validation` — `{"grounded": bool, "unsupported_sentences": [str], "invalid_cites": [int]}`
5. `event: done` — `{"message_id": str, "finish_reason": str}`
On failure at any point: `event: error` — `{"message": str}`.

### Conversations
- `GET /api/conversations` → `[{"id","title","created_at","updated_at","message_count"}]`
- `GET /api/conversations/{id}` → `{"id","title","messages":[{"id","role":"user"|"assistant","content","created_at","sources":[...as above],"meta":{...meta event}}]}`
- `PATCH /api/conversations/{id}` body `{"title": str}` → 200
- `DELETE /api/conversations/{id}` → 204

### Documents (user uploads)
- `POST /api/documents` multipart field `file` → `{"id","filename","status":"pending"}`
- `GET /api/documents` → `[{"id","filename","status":"pending"|"processing"|"ready"|"error","chunk_count":int,"error":str|null,"created_at"}]`
- `DELETE /api/documents/{id}` → 204

### Search (retrieval only, debug)
- `POST /api/search` body `{"query": str, "top_k": int=20, "include_debug": bool=false, "doc_ids": [str]|null}` →
  `{"results": [{...source fields, "text": str, "ce_score": float, "authority_score": float, "final_score": float}], "low_confidence": bool, "filtered": {...}, "debug": {"rewrites": [str], "hyde": str|null, "citation_shortcircuit": [str], "candidates_pre_filter": int, "candidates_pre_rerank": [{chunk_id, citation, rrf_score}], "timings_ms": {...}} | null}`

### Law / corpus explorer
- `GET /api/law/{citation}` (URL-encoded, e.g. `Employment%20Act%201968%2C%20s%2014`) → `{"found": bool, "chunks": [{...source fields, "text": str}]}`
- `GET /api/law/{citation}/history` → `{"versions": [{"sso_version_date","fetched_at","source_url"}]}`
- `GET /api/law/{citation}/citing` → `{"citing": [{"citation","court","decision_date","treatment"}]}`
- `GET /api/corpus/toc?doc_type=&q=` → `[{"doc_id","title","citation","doc_type","status","authority_tier"}]`
- `GET /api/corpus/doc/{doc_id}` → `{"doc_id","title","citation","status","source_url","sso_version_date","tree":[{"label","citation","chunk_id"|null,"children":[...]}]}`
- `GET /api/chunks/{chunk_id}` → full chunk: `{...source fields, "text","context","doc_id"}`

### Ops
- `GET /api/health` → `{"status":"ok"|"degraded","models":{"embedder":str,"reranker":str,"loaded":bool},"qdrant":{"sg_law":int,"user_docs":int},"corpus":{"acts":int,"subsidiary_legislation":int,"judgments":int,"practice_directions":int,"repealed":int},"llm":{"provider":str,"configured":bool},"last_sync":str|null}`
- `POST /api/admin/sync` body `{"force": bool=false}` → `{"started": bool, "reason": str}` (refuses outside 05:00–07:00 SGT unless seeding)

### Frontend requirements (spec Part 6, summarised for the subagent)
Chat w/ streaming + `[CITE:n]` chips → side panel (`GET /api/chunks/{id}`) with hierarchy path + SSO link; conversation sidebar (rename/delete/search); per-answer status chip (primary source tier, in-force date, warning badge when any source repealed/overruled); source explorer (toc → doc tree → provision view w/ history + citing); documents page (drag-drop upload, progress polling, delete, "ask about this document" scoping); collapsible retrieval inspector fed by `/api/search` `include_debug`; persistent non-dismissible legal-information disclaimer; AGC attribution wherever legislation shows; corpus-last-synced timestamp; designed empty/low-confidence states.

## API Contract v2 addendum (2026-10-07) — SingLaw UI integration

All v1 endpoints above remain unchanged. Additions:

### Chat request extensions — `POST /api/chat`
Body gains two optional fields: `{"message", "conversation_id", "doc_ids", "business_id": str|null, "regenerate": bool=false}`.
- `business_id`: the business's documents are added to `doc_ids`, and the business profile (name + description) is injected into generation as the user's factual context (never authority). The `meta` event gains `"business_id": str|null`.
- `regenerate: true` requires `conversation_id`; the backend deletes the conversation's last assistant message, ignores `message`, and answers the last user message again without inserting a new user turn. Stream shape identical.

### Conversations
- `POST /api/conversations` body `{"title": str|null}` → 201 `{"id","title","created_at","updated_at","message_count":0}` (create empty; the UI navigates to `/chat/$id` then streams).
- `GET /api/conversations/{id}` messages gain `"feedback": "up"|"down"|null`.

### Businesses (workspaces with their own documents)
- `GET /api/businesses` → `[{"id","name","description","icon","document_count","created_at"}]`
- `POST /api/businesses` body `{"name": str, "description": str="", "icon": str="Building2"}` → 201 business. 403 `{"detail": "..."}` when the plan limit (`max_businesses`, default 3) is reached.
- `PATCH /api/businesses/{id}` body any of `{name, description, icon}` → business
- `DELETE /api/businesses/{id}` → 204 (its documents are deleted too — UI must confirm)
- `GET /api/businesses/{id}/documents` → same shape as `GET /api/documents`
- `POST /api/documents` gains optional multipart field `business_id`; `GET /api/documents` items gain `"business_id": str|null`.

### Feedback
- `POST /api/feedback` body `{"message_id": str, "rating": "up"|"down", "comment": str|null}` → 201 `{"ok": true}` (upsert per message).

### Content (editorial, real-answer backed)
- `GET /api/content/suggestions?mode=personal|business` → `{"suggestions": [{"label": str, "text": str}]}` — curated defaults merged with the most-asked real user questions (≥3 occurrences, last 30 days), max 4.
- `GET /api/content/discoveries` → `{"discoveries": [{"id","title","body","question","citation","url"}]}` — curated "did you know" items from `data/content/discoveries.json`; `question` is answered live by the RAG.

### Billing
- `GET /api/billing/plans` → `{"plans": [{"id": "personal"|"business"|"teams", "name", "description", "price_monthly_sgd": number|null, "price_yearly_sgd": number|null, "features": [str], "limits": {"businesses": int|null, "documents": int|null}, "featured": bool, "available": bool}]}`
- `GET /api/billing/status` → `{"plan": str, "usage": {"conversations": int, "messages": int, "documents": int, "businesses": int}, "limits": {"businesses": int|null, "documents": int|null}, "checkout_available": bool}`
- `POST /api/billing/checkout` body `{"plan_id": str, "interval": "monthly"|"yearly"}` → `{"url": str}` when Stripe is configured (`STRIPE_SECRET_KEY` + `STRIPE_PRICE_IDS`), else 503 `{"detail": "Checkout is not configured yet"}` — UI then offers the waitlist.
- `POST /api/billing/waitlist` body `{"email": str, "plan_id": str}` → 201 `{"ok": true}`
- `POST /api/billing/webhook` — Stripe `checkout.session.completed` sets the active plan (kv `plan`).

### Corpus explorer (unchanged v1, used by the new Sources page)
`GET /api/corpus/toc`, `GET /api/corpus/doc/{doc_id}`, `GET /api/chunks/{chunk_id}`, `GET /api/law/{citation}/history`, `GET /api/law/{citation}/citing`, `POST /api/search`.
